# NBA MVP Prediction — Design Spec
**Date:** 2026-05-05

## Goal

Improve the existing NBA MVP prediction notebook by:
1. Switching from binary classification to **vote share regression** for more nuanced top-3 ranking
2. Adding a **neural network (MLP)** alongside XGBoost for side-by-side comparison
3. Generating a **standalone static HTML report** (`report.html`) with charts and validation results

## Architecture

The existing `NBA_MVP.ipynb` is restructured into 7 clearly labeled sections:

1. Imports & config
2. Data loading & cleaning (unchanged)
3. Feature engineering (minor additions)
4. Model training — XGBoost Regressor
5. Model training — MLP Regressor
6. Side-by-side comparison & validation
7. HTML report generation → writes `report.html`

No new files are introduced. Everything stays in the single notebook.

## Data & Features

**Target variable:** `share` (continuous 0–1, vote share). All qualifying players are included (non-vote-getters have share=0). This eliminates the need for `scale_pos_weight` and class imbalance handling.

**Qualifying threshold:** Same as current — `g >= 50` and `mp_per_game >= 25`.

**New features added:**
- `pts_rank_in_season` — per-season rank by `pts_per_game` (corrects for scoring-era drift)
- `vorp_rank_in_season` — per-season rank by `vorp`
- `per_rank_in_season` — per-season rank by `per`

**Features retained from current notebook:**
`trb_per_game`, `ast_per_game`, `pts_per_game`, `ts_percent`, `usg_percent`, `vorp`, `per`, `vorp_x_win`, `per_x_win`, `usg_x_win`, `win_pct`, `playoffs`

**Preprocessing:**
- XGBoost: no scaling needed
- MLP: `StandardScaler` applied to all features before fitting

Both models train on the identical feature set for a fair comparison.

## Models

### XGBoost Regressor
- `XGBRegressor` with `objective='reg:squarederror'`
- Hyperparameter tuning via `RandomizedSearchCV` (50 iterations, same parameter grid as current minus `scale_pos_weight`)
- No preprocessing required

### MLP Regressor
- `sklearn.neural_network.MLPRegressor`
- Hidden layers: `(64, 32, 16)`, ReLU activation, `max_iter=500`
- Tuned via `RandomizedSearchCV` over: `learning_rate_init` ([0.001, 0.01, 0.1]), `alpha` ([0.0001, 0.001, 0.01]), `hidden_layer_sizes` ([(64,32,16), (128,64,32), (32,16)])
- Features scaled with `StandardScaler` before fitting

### Validation Strategy
**Leave-one-season-out cross-validation** — train on all seasons except one, predict that season, repeat for each season 2010–2024. This mirrors real-world use (future season is always unseen).

**Primary metric:** Spearman rank correlation between predicted and actual vote share — measures correct ranking of top 3.

**Secondary metrics:**
- RMSE
- Top-3 overlap rate (how often the predicted top 3 matches the actual top 3)
- Winner accuracy (did the predicted #1 match the actual winner)

## HTML Report

Generated by the final notebook cell using a Jinja2 template. Self-contained — all charts embedded as Plotly HTML, no server required. Open with `open report.html`.

**Report sections:**

1. **2025 MVP Race** — horizontal bar chart showing predicted vote share for top 3 candidates, XGBoost and MLP bars side-by-side per player
2. **Model Comparison** — table of Spearman correlation, RMSE, top-3 overlap rate, and winner accuracy for each model across validation seasons
3. **Feature Importance** — XGBoost feature importance bar chart (built-in `feature_importances_`)
4. **Historical Validation** — per-season table (2010–2024) showing predicted vs actual top 3 for both models, with summary hit rates

## Success Criteria

- MLP and XGBoost both produce Spearman rank correlation > 0.7 on leave-one-season-out validation
- Top-3 overlap rate >= 2/3 for both models on average across seasons
- `report.html` opens in a browser with no dependencies and displays all 4 sections correctly
- Notebook runs end-to-end without errors from a clean kernel restart
